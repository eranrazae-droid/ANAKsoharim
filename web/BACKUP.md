ומה לעשות כדי לקבל את הכל בחזרה.

## מה מגובה היום

כל הקוד של האתר החדש (`web/`) וכל מערכת התפעול (`ops/`) שמורים
בשלוש שכבות נפרדות:

| איפה | מה יש שם | מי מחזיק |
|---|---|---|
| GitHub — `eranrazae-droid/ANAKsoharim` | כל הקוד, וכל היסטוריית השינויים מהיום הראשון | הענן |
| קובץ גיבוי `.bundle` | אותו דבר בדיוק, בקובץ אחד שאפשר לשמור בכל מקום | אתה |
| Vercel | כל גרסה שעלתה לאוויר, אפשר לחזור לכל אחת בלחיצה | הענן |

שלוש שכבות שאינן תלויות זו בזו. גם אם אחת נעלמת, השתיים
האחרות מספיקות כדי לשחזר הכל.

**גיבוי אחד לא מספיק.** הכלל המקובל הוא שלושה עותקים, בשני
מקומות שונים לפחות, ואחד מהם לא בענן. הקובץ שאצלך הוא העותק
שלא בענן — שמור אותו במקום שאתה שולט בו: מחשב, כונן חיצוני
או Google Drive פרטי.

לפני שעוברים לשינוי הבא. אין מצב שבו שינוי קיים רק על מחשב אחד.
זה כלל עבודה קבוע ולא משהו שמחליטים עליו בכל פעם מחדש.

**כל לילה ב-23:00.** משימה אוטומטית בודקת אם היו שינויים באותו
יום. אם היו — היא מייצרת קובץ גיבוי חדש, מוודאת שהוא באמת נפתח,
ושולחת אותו אליך עם רשימה קצרה של מה השתנה. אם לא היו שינויים
היא לא שולחת כלום, כדי לא להציף.

כך תמיד יש שתי נקודות שחזור: הרגעית בענן, והיומית שאצלך.

## איך משחזרים הכל

מקובץ הגיבוי, גם בלי גישה לאינטרנט ובלי GitHub:

```
git clone anak-backup-YYYY-MM-DD.bundle anak
cd anak/web
npm ci
npm run build
```

נמדד בפועל: פחות מדקה מהקובץ ועד אתר בנוי ורץ.

מ-GitHub, אם הוא זמין:

```
git clone https://github.com/eranrazae-droid/ANAKsoharim.git
```

**לחזור לגרסה קודמת של האתר החי** — ב-Vercel, בלשונית
Deployments, בוחרים גרסה קודמת ולוחצים Promote to Production.
פעולה של שניות, בלי לגעת בקוד.

## מה **לא** מגובה בקוד — ודורש פעולה שלך

הקוד מגובה במלואו. הדברים הבאים חיים מחוץ לקוד, ואם הם יאבדו
אף גיבוי של הקוד לא יחזיר אותם:

1. **סיסמאות ומפתחות שמוגדרים ב-Vercel** — כתובת יעד הלידים,
   מפתח שליחת המיילים, מפתח האזור האישי. הם לא נשמרים בקוד
   בכוונה, כי קוד עם סיסמאות בתוכו הוא פרצה. שמור אותם אצלך
   במנהל סיסמאות.
2. **הדומיין `03-5189189.co.il`** — הנכס הכי חשוב שיש לעסק
   באינטרנט. ודא שהוא רשום על שמך, שהחידוש אוטומטי, ושיש לך
   את פרטי הכניסה לחברת הרישום.
3. **הנתונים של מערכת התפעול** — הקליטות, המשימות והתמונות
   יושבים ב-Firebase, לא בקוד. הקוד של המערכת מגובה; המידע
   שנצבר בה לא. כדאי להגדיר ייצוא אוטומטי של Firestore.
4. **תמונות הרכבים ופרטי המלאי** — מגיעים מהמערכת החיצונית,
   ולכן הם באחריות אותה מערכת ולא שלנו.
5. **חשבון הגוגל של העסק** — הביקורות והמפה. ודא שיש לך גישת
   בעלים ולא רק גישת ניהול.
