# העברה לקלוד — צ׳אט AI לרכב בטלפון

יש שכבת תצוגה חדשה מאחורי `?ui2m=1` ב־`ops/js/ui2-mobile.js` ו־`ops/css/ui2m.css`. זהו UI בלבד; אין חיבור רשת חדש ואין תשובות מלאכותיות המוצגות כמידע אמיתי.

## חוויית השימוש שאושרה
- מנהל: יומן מימין, צ׳אט AI באמצע, ובשמאל ״הכל״ בבית ו״בית״ בשאר המסכים.
- נהג: בית מימין, צ׳אט AI באמצע, וואטסאפ למנהל משמאל.
- הצ׳אט בחלונית מעל המסך הקיים, בלי ניווט או בנייה מחדש של טופס שמתחתיה. סגירה מחזירה לאותה טיוטה. שיחה והקלדה נשמרות בזיכרון במהלך העבודה; החלפת משתמש מאפסת אותן.
- מטרת הצ׳אט: מידע מעשי על הרכב — ספייר, מצבר, אבזור ומיקום רכיבים.
- הנהג מזין רישוי בן 7–8 ספרות. מילוי אוטומטי כבר קיים כאשר פתוחה קליטה ששייכת לנהג הנוכחי; להרחיב לטפסים נוספים רק כשהזיהוי חד־משמעי, ולהראות בבירור לאיזה רכב מתייחסים. היסטוריית הבקשה חייבת להיות מופרדת לפי משתמש ורישוי.

## החיבור המוכן
להגדיר `window.AnakMobileAI.ask` במודול נפרד. שכבת העיצוב קוראת:

```js
await window.AnakMobileAI.ask({
  plate,       // ספרות בלבד
  message,
  history,     // [{role, content}] — רק לרישוי הנוכחי
  signal       // AbortSignal, לביטול בעקבות החלפת משתמש
});
// { answer: string, sources?: [{title: string, url: string}] }
```

השכבה מציגה טקסט כטקסט, וקישורי מקור רק ב־HTTPS. אין להחזיר HTML. המשתמש רואה מצב ״עדיין לא מחובר״ עד שהמתאם זמין. יש לטפל בתשובה חסרה, שגיאה, timeout ובקשה שהתבטלה; לא לשייך תשובה ישנה למשתמש חדש. אם מוסיפים streaming, להתאים את החוזה במפורש.

## זיהוי ומקורות
1. לבדוק ולמחזר את חיפוש הרישוי הממשלתי הקיים בפרויקט דרך השרת; לא לבנות מקור כפול בלי צורך. מאגר משרד התחבורה מזהה פרטי רישום ודגם, ואינו מבטיח מידע מלא לכל רכב.
2. להציג כרטיס זיהוי מאומת עם יצרן, דגם, שנת ייצור ורמת גימור ככל שהם זמינים, יחד עם מקור ומועד השליפה. הכרטיס וחיבור נתוני הרכב עדיין צריכים מימוש.
3. משרד התחבורה אינו מקור מספק להתאמת מצבר או לקיום ספייר. להשלים מספר הרכב, מידע יצרן/יבואן וקטלוג התאמה מוסמך. לתת מקורות, לציין חוסר ודאות ולבקש גרסה/צילום/פרט מזהה כשההתאמה אינה חד־משמעית. לא לנחש מפרט.
4. מפתחות AI והגישה לשירותים בשרת בלבד, באמצעות מנגנון האימות וההרשאות הקיים. לא לחשוף מפתחות בדפדפן ולא לתת למודל הרשאות כתיבה למסדי התפעול. לקבוע מגבלות שימוש, זמן ועלות.
5. חיפוש משרד התחבורה: https://data.gov.il/he/datasets/ministry_of_transport/private-and-commercial-vehicles . לא להניח URL או resource ID של API בלי לבדוק שהם עדכניים.

## אימות לפני פרסום
- לבדוק טיוטת קליטה פעילה ומילוי משימה: פתיחה/סגירה/מקלדת/החלפת רכב לא משנות את הנתונים או גורמות לשליחה.
- בידוד בין נהגים ובין רישויים, כולל תשובה איטית שמגיעה אחרי החלפת משתמש.
- מספר רכב לא תקין/לא נמצא, חוסר התאמה, השבתת מקורות ושרת, חיבור איטי וניתוק.
- טלפון 390×844, מקלדת פתוחה, RTL, רוחבים 320 ו־900; מחשב ומסך איברהים נשארים ללא שינוי.
- לשמור את המתג הנפרד ואת התנהגות הכיבוי. לפרסם רק לאחר בדיקת PR; להשלים את עדכון גרסת ה־SW בעת ההטמעה בהתאם למדיניות הפרויקט, בלי לשנות את העיצוב של המחשב.
